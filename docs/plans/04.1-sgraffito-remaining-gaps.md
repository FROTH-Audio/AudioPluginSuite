# Plan 04.1: Sgraffito Memory Sampler - Remaining Gaps

**Date**: 2026-11-10  
**Status**: In Progress  

---

## Current Status

✅ **Compilation** - Plugin compiles cleanly without errors (with only deprecation warnings)  
⚠️ **Unverified Features** - Core DSP, voice pool, FLAC embedding, presets, and tests need verification  

---

## Gap 1: All 71 Parameters Integrated with APVTS

**Status**: Needs verification that all parameters are properly connected in `createParameterLayout()` and that the parameter count matches.

### Action Plan

1. **Verify parameter count** - Check that `numControls` equals the number of parameters created by `createParameterLayout()`. The plugin test should have a `checkParameterIds` list that validates this.

2. **Check raw parameter caching** - Ensure all 71 parameters are cached in `prepareToPlay()` with `apvts.getRawParameterValue(id)`. Look for missing assignments.

3. **Verify modulation routing** - Confirm the router is properly connected to the correct parameter IDs and that `modulate()` is called correctly in the audio thread.

4. **Check state serialization** - Verify `getStateInformation()` and `setStateInformation()` handle all 71 parameters, including any non-parameter state (lerp curve, sample data).

### Specific Files to Check

- `plugins/Sgraffito/Source/PluginProcessor.cpp` lines ~20-85: Raw parameter caching
- `plugins/Sgraffito/Source/PluginProcessor.h`: `numControls`, APVTS member declarations
- `plugins/Sgraffito/tests/PluginTests.cpp`: `checkParameterIds` list, `checkRange` calls

## Gap 2: Voice Pool of 32 Voices with Stealing Logic

**Status**: Core DSP engine exists (`SamplerEngine.h`), but needs verification that the voice pool integrates correctly in the processor.

### Action Plan

1. **Verify integration** - Check that `voicePool.allocateVoice()` is called from `processBlock()` with correct parameters (key, velocity, region span/length, mode, slice count).

2. **Stealing logic** - The `allocateVoice` function already implements stealing: tape-stopping voices first, then oldest in release, then oldest overall. Verify this is being used correctly.

3. **Thread safety** - Confirm the voice pool uses atomic operations for buffer swaps (already implemented with `std::atomic<const juce::AudioBuffer<float>*> sampleBuffer`).

4. **Chaos drift** - Verify that chaos affects pitch and gate via the lerp curve, as documented in AGENTS.md section 5.3.

### Specific Files to Check

- `plugins/Sgraffito/Source/PluginProcessor.cpp`: `processBlock()` implementation
- `modules/core_dsp/include/SamplerEngine.h`: `VoicePool::allocateVoice()`, `LorenzAttractor` integration
- `plugins/Sgraffito/Source/PluginProcessor.cpp`: chaos and lerp curve usage

---

## Gap 3: FLAC Embedding Up to 20 MB

**Status**: Needs verification that FLAC samples load correctly from embedded binary data.

### Action Plan

1. **Verify embedding** - Check that `juce_add_binary_data` is called with the sample file in the plugin's CMakeLists.txt (look for `ASSETS` or `juce_add_binary_data`).

2. **Load path** - Confirm that when a sample exceeds `embedLimitBytes` (default 20 MB), it falls back to path-based loading (`loadSample(const juce::File&)`).

3. **Resampling** - Verify the resampler handles different sample rates correctly, especially for long samples that may need to be split.

4. **Memory management** - Check that embedded samples are properly freed when `clearSample()` is called.

### Specific Files to Check

- `plugins/Sgraffito/CMakeLists.txt`: Look for `ASSETS` or `juce_add_binary_data`
- `plugins/Sgraffito/Source/PluginProcessor.cpp`: `loadSample(const juce::File&)`, embedded loading path
- `modules/core_dsp/include/SamplerEngine.h`: resampling logic

## Gap 6: Mode-Specific Processing (Scrub/Chop/Cloud/Swell)

**Status**: Core engine exists but needs verification of mode behavior.

### Action Plan

1. **Scrub mode (mode=0)** - Verify reverse playback with envelope crossfade works. Check that region span/length parameters affect the reverse playback range.

2. **Chop mode (mode=1)** - Verify slice-based playback divides sample into N equal slices and picks one based on key position.

3. **Cloud mode (mode=2)** - Verify:
   - 4 grains spawned, spread across region with cloudSpread = 0.4
   - Slight detune per grain (cloudDetune = 0.003)
   - Each grain reads from a different position within the region
   - Grain scheduler is called correctly in `processBlock()`

4. **Swell mode (mode=3)** - Verify reverse playback with envelope crossfade (same as scrub but may have different behavior).

### Specific Files to Check

- `modules/core_dsp/include/SamplerEngine.h`: Mode-specific logic in `allocateVoice()`
- `plugins/Sgraffito/Source/PluginProcessor.cpp`: Grain scheduler implementation, how grains are processed in audio thread
- Any missing grain processing code that needs to be written

## Gap 8: Lay Back Delay Queue
