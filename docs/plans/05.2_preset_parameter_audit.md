Purpose: a cross-cutting audit of the preset system against the live plugin parameters, after the
parameter, preset, UI and sampler work of plans 03–05. The audit asks five questions and answers them
from the code, the preset bank, the tests and the documentation:

1. **Parameters vs presets.** Compare the parameters of the plugins with the preset parameters. If
   there are any "new" parameters that no factory preset covers (added after the bank was authored,
   or not yet added to the authoring schema), new presets or changes to existing presets are needed.
2. **Cleanup.** Is there anything stale in the folders or the documents of the preset area?
3. **Documentation up to date.** Do `AGENTS.md`, `README.md`, `CHANGELOG.md`, the plugin READMEs and
   the plan documents still say what the code does?
4. **Enough tests?** Is the existing test set sufficient for the audit's findings, or does the
   parameter/preset comparison need new tests (for example a check that the authoring schema covers
   every live parameter)?
5. **Refactorings.** Are there refactorings that this review uncovers and that are worth doing now?

Detailed results of this audit are documented in `05.3_preset_parameter_audit_results.md`.

## 1. Method

### 1.1 Parameter ↔ preset comparison

1. Collect the live parameter IDs per plugin from `plugins/<Name>/Source/PluginProcessor.h` /
   `createParameterLayout()`.
2. Collect the keys of `SCHEMA` per plugin from `tools/preset_data.py`.
3. Compare sets exactly; report missing (`live` only) and unknown (`SCHEMA` only) entries.
4. Run `python tools/audit_bank.py` and record the verdict.
5. For every live parameter, check whether it appears in at least one factory preset delta with a
   non-default value; judge sparse-but-intended (global/derivative parameters, routing slots that no
   preset uses) versus a genuine coverage gap that warrants a new or changed preset.

### 1.2 Cleanup

- Stale artefacts in `modules/suite_presets/` (Pro-overlay skeletons, obsolete files).
- Stale documents in `docs/plans/` and elsewhere that still describe removed behaviour.
- Untracked files under `docs/plans/` (known: the directory is untracked; do not delete anything
  there without showing the owner first).

### 1.3 Documentation up to date

- `AGENTS.md` sections 4, 5.5, 6, 7, 10, 12, 13.
- `README.md` (root) preset/parameter sections, CMake flag table.
- `CHANGELOG.md` (Unreleased).

### 1.4 Enough tests?

| Bank audit | `python tools/audit_bank.py` | pass, 95 presets |

| New parameters since authoring | diff parameter history / plan entries; re-scanned 2026-11-12 | LFO Offset + Mod Delay in `SCHEMA`; DS `pan` implemented but missing from `SCHEMA` (live gap, now tracked) |

Outcome: if the sets are equal and the audit passes, the preset side is in step with the parameter
side; any new parameter must be added to `SCHEMA` and presets re-authored before the next release.
If a new parameter is missing from the schema, the fix is: add it to `SCHEMA`, regenerate the bank,
run the audit, and decide the preset coverage (new preset or changed existing preset).

### Check 2 — Cleanup

- Resolve contradictions between code comments, CMake, README and prose.

### Check 3 — Documentation up to date

### Check 4 — Enough tests?

- Compare documented test counts with the actual test declarations.
- Check whether the parameter/preset comparison is enforced anywhere automatically beyond
  `audit_bank.py`.
