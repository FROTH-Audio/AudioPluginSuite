## Executive summary

Cyclical is a new **instrument** (not an effect) that plays four loaded audio loops with creative
playback modes. It does not record; loops come from the factory bank, the user's disk, or the
embedded default set. Each slot has its own region, speed, direction (forward, reverse,
ping-pong with a turn-around randomised per retrigger), a phase-vocoder-free **granular** mode,
and velocity scaling. Everything can be locked to the host grid with a quantised start and
swing, and the whole instrument runs from four fixed MIDI keys.

- **35 parameters** (5 global, 28 per-slot over 4 slots, 2 playback).
- **15 factory presets**, each carrying four `embedded:` loops; a 12-loop embedded library.
- **Two editor pages** (SLOTS, GLOBAL) under R4 (980 × 700).
- **No recording, no effect mode, no modulation** in this plan (all pinned as later work).
- Plugin identity: folder `Cyclical`, code `Cycl`, accent `#8FA3B8`.

## Scope decisions (what this is, and what it deliberately is not)

Idea 2.10 proposed an effect/instrument hybrid with recording, configurable start/end, speed,
direction, quantisation and a slot grid. The owner re-scoped it on 2026-11-18. This table records
the decisions so the omissions are intentional.

| Topic | Decision | Consequence in this plan |
|---|---|---|
| Recording | **Out of scope** (pinned as a future idea) | No audio input bus at all; the plugin is output-only |
| Slots | **4** | One 2×2 grid; one **active** voice per slot plus at most one fading tail (4 sounding slots) |
| Mode | **Instrument only** | `IS_SYNTH NEEDS_MIDI_INPUT`, no `IS_MIDI_EFFECT`; effect mode deferred |
| Loop sources | **Hybrid** (option C) | Four `embedded:` factory defaults + per-slot disk loading with a fallback folder |
| Direction | Forward, Reverse, Ping-Pong | Per-slot choice; ping-pong can randomise its **turn-around points** on retrigger only |
| Pitch/time independence | **Not in this plan** (simple detune is enough) | `pitchShift` changes speed and pitch together, like a tape varispeed |
| Granular | **On/off per slot in Phase 1** | Fixed 80 ms grains, one grain at a time; grain size/density/spread deferred |
| Loop-seam crossfade | **Global** | One `crossfadeLength` for all slots |
| MIDI mapping | **Fixed, one note per slot** (C4–D#4 = 60–63) | No mapping editor; documented on the slot cards and in the manual |
| Trigger mode | **Switchable** | `Latch` (note-on starts, runs until retrigger) / `Gate` (plays while held) |
| Chords / layering / flexible mapping | **Deferred** (not Phase 2) | Four notes can still sound together, one per slot |
| Modulation (`SuiteModulation::Router`) | **Deferred** | No `MODULATION` argument in Phase 1; no router parameters |
| State version | **1** (new plugin) | No migration; `loopNPath` properties are additive |

## Architecture

### 1. `modules/core_dsp/include/LoopEngine.h` (new, header-only)

Namespace `CoreDSP::Loop`. Pure playback maths, no JUCE GUI, no allocation on the audio thread.
Add it to the `CoreDSP.h` umbrella (`#include "LoopEngine.h"` alongside the ten existing engines).

```cpp
enum class Direction { forward, reverse, pingPong };

struct Source
{
    const float* const* channels = nullptr;   // non-owning; owned by LoadedLoop
    int    numChannels = 0;
    int    numFrames   = 0;
    double sourceSampleRate = 0.0;
};

struct Region
{
    int    startFrame   = 0;
    int    lengthFrames = 1;                  // effective length, already clamped by the caller
    double speed = 1.0;                       // 0.25 .. 4.0
    Direction direction = Direction::forward;
    bool   granular = false;
    int    crossfadeFrames = 0;               // 0 .. 500 ms, converted at the host rate
};

class Voice
{
public:
    void prepare (double hostSampleRate);
    void start (const Source&, const Region&, double pitchRatio,
                double gain, std::uint32_t triggerSeed);
    void release();                            // Gate note-off: 5 ms fade, then inactive
    void cut();                                // retrigger: 2 ms fade, then inactive
    void render (juce::AudioBuffer<float>& out, int startSample, int numSamples);
    void reset() noexcept;                     // prepareToPlay / transport stop: silent, inactive
    bool   isActive() const noexcept;
    const Source* source() const noexcept;     // captured in start(); see the lifetime rule below
    double playheadNormalised() const noexcept;// 0..1 over the *fresh* span, for the UI
};
```

Rules the implementation and tests share:

- **Rate** = `region.speed × pitchRatio × sourceSampleRate / currentSampleRate`.
  `pitchRatio = 2^(pitchShift/12)`, and `currentSampleRate` is read **per block** (not cached at
  load), so a host rate change mid-note keeps playing at the right speed with no reload. Unlike
  Sgraffito's `readAndResample`, `LoadedLoop` keeps its source rate — this is why `speed` and
  `pitchShift` fold into one rate. Mono sources are read once and copied to every output channel
  (the Sgraffito rule; never index the source by the output channel number).
- **Forward** (crossfade `X`, `X = min(crossfadeFrames, lengthFrames / 2)`): the **fresh span** is
  `[start + X, end)`; the last `X` frames (`[end − X, end)`) blend the tail with the head read at
  `start + (p − (end − X))`, weight `t = (p − (end − X)) / X` rising 0→1, and playback **resumes at
  `start + X`**, not at `start`. `[start, start + X)` is a pre-roll heard only inside the blend.
  At `X = 0` this is the plain hard wrap `end → start`, bit-exact.
- **Reverse** is exactly the forward rule in the mirrored coordinate `q = (end − 1) − p`: fresh span
  `(start, end − 1 − X]`, fade over `[start, start + X)` blended with `(end − 1 − X, end − 1]`,
  resume at `end − 1 − X`.
- **Ping-pong**: direction flips at both bounds with no wrap, so no seam blend is applied. The
  reflection does **not** repeat the boundary sample: `p = 2·bound − p` (then continue), not
  `p = bound` twice.
- **Crossfade law**: linear. For correlated material (the seam of a well-made loop) the blend sums to
  unity, so there is no level dip; for uncorrelated material it dips to −3 dB at the midpoint. This
  is deliberate — equal-power would *boost* correlated content by +3 dB, which is worse for loops.
  The test states the expectation per fixture rather than "preserves energy" in the abstract.
- **Ping random** (`pingRandom`): drawn **once per trigger** from `hash(triggerSeed)`, it insets the
  two turn-around points by `a, b ∈ [0, 0.25] × lengthFrames`, so the traversal bounds become
  `[start + a, end − 1 − b]`. The **rate is untouched**, so the cycle time changes while the pitch
  stays put — a rate multiplier would detune each retrigger against `pitchShift` and the other
  slots. With `pingRandom` off, `a = b = 0`.
- **Granular**: grains are `kGrainMs = 80` ms long, one at a time per voice, half-sine windowed.
  The **first** grain starts at `start` (a deterministic, audible attack); later grains start from
  `hash(triggerSeed, grainIndex)` inside the region and wrap within it, reading forward at the
  pitch-shifted rate. `speed`, `direction` and `pingRandom` are ignored in granular mode;
  `start`/`length` define the region. 12.5 grains/s is a stutter, not a cloud — the manual and the
  preset descriptions say so; grain size/density/spread become parameters in a follow-up.
- **Gain**: `noteVelocity × slotVelocity/100`, applied at `start()` (so a velocity change is heard
  from the next trigger, not mid-note), with a 5 ms attack ramp. `release()` and `cut()` ramp down
  before the voice goes inactive.
- **Lifetime**: `start()` captures the `Source` (pointers, counts and rate) and the voice holds it
  until it goes inactive, so a mid-voice loop swap stays valid through the retirement queue.
- **No reads outside the region or buffer.** The region is clamped by the caller; the engine clamps
  again defensively. The tests check the buffer edges.

### 2. Sample per slot (`plugins/Cyclical/Source/LoopSlot.h`)

```cpp
struct LoadedLoop
{
    juce::AudioBuffer<float> buffer;       // as decoded, at its own sample rate
    juce::String sourcePath;               // file path, or "embedded:<file name>"
    double sourceSampleRate = 0.0;
};
```

- Each slot owns `std::atomic<const LoadedLoop*> current` plus a **retirement queue capped at two
  generations** (`std::deque<std::unique_ptr<LoadedLoop>>`), exactly the plan 09 1.1 / Sgraffito
  pattern: a block that started before a swap can still read the old buffer, and two installs inside
  one block must not free it. The audio thread only ever loads the atomic; it never touches the
  queue.
- Disk loads are **asynchronous**: a `juce::ThreadPool` member declared last (destroyed first), a
  per-slot generation stamp so the latest request wins, and a `LoadLifetime` token so a queued
  handoff is a no-op after destruction. The install runs on the message thread through one shared
  `finishLoopLoad()` path (retire → swap → sync the `loopNPath` property).
- Embedded loads (`BinaryData` → `MemoryInputStream` → `AudioFormatReader`) are synchronous.
  `registerBasicFormats()` reads WAV/AIFF only, so those are the accepted file patterns
  (`*.wav;*.aiff;*.aif`).
- Paths live in the state as `loop1Path` … `loop4Path` **attributes on `<PARAMETERS>`**, never APVTS
  parameters (the `lerpCurve` / `samplePath` route; **no SCHEMA entry**, or the schema-coverage
  audit flags it as having no live parameter).
- Resolution rule (plan 07 semantics): an **empty tree** = INIT → all four slots reset to the
  embedded defaults; an `embedded:` URI → `loadEmbeddedLoop` (URI is the file name, resource name
  derived); an existing file → load; a missing file → try the same file name in
  `userDocuments/AudioSuite/Cyclical/Samples`, and if that fails keep the current loop, set
  `loopMissing[slot]` and show a per-slot overlay with click-to-locate.
  `applyLoopsFromState` reads the **incoming** tree (the plan 07 phase 1 lesson).

### 3. Processor

- **Fixed MIDI map**: notes 60, 61, 62, 63 (C4, C#4, D4, D#4) trigger slots 1–4. Other notes are
  ignored. Note-off is matched per slot (release in Gate, ignored in Latch).
- **Voices**: each slot owns `Voice voices[2]`; `voices[0]` is active, `voices[1]` is the fading tail.
  A retrigger `cut()`s the active voice into the tail (stopping a tail that is still fading — a ≤2 ms
  cut is inaudible), then starts the new voice. So at most **two** renders per slot, four slots can
  sound at once, and there is no pool and no stealing rule to get wrong.
- **Channel rule** (the host-load test hands an instrument a **mono** buffer —
  `jmax (1, getTotalNumInputChannels())` — while reporting two outputs): every loop is bounded by
  `buffer.getNumChannels()`, never by `getTotalNumOutputChannels()`. The slot mix folds into the
  available width (mono: the pan's L/R gains summed), and `prepareToPlay` stores the width it will
  actually write. See also the host-test item in [Testing](#testing-strategy).
- **Beat clock**: follows the host's PPQ when a playhead is present and playing; otherwise it
  accrues `numSamples × bpm / (60 × sampleRate)` from the host tempo, falling back to 120 BPM with
  no playhead. Like the effects' synced LFOs, the clock only accumulates, so loops never jump on
  relocate or loop.
- **Quantised start**: `quantize` maps to a grid of {Off, 1/16, 1/8, 1/4, 1/2, 1 bar} = {0, 0.25,
  0.5, 1, 2, 4} beats (4/4 assumed; the host time signature is not read). A trigger is scheduled at
  `ceil(beat/grid − 1e-9) × grid`, and odd grid indices shift by
  `CoreDSP::Sequencer::swingBeats (gridIndex, swing, grid)` — the seeded, already-tested suite
  convention (100 % = a full step), not a second swing formula.
- **Pending triggers**: a bounded array (`4` entries, one per slot). Rules the tests pin:
  a second trigger on the same key **replaces** the pending one; in Gate mode a note-off before the
  scheduled start **cancels** it (a tap shorter than the grid step produces nothing); `prepareToPlay`,
  `reset()`, a loop swap on that slot, and a transport stop flush the pending list.
- **Trigger seed**: `std::atomic<std::uint32_t> triggerCounter` incremented per trigger and passed as
  `triggerSeed`, so the ping-random turn points and the granular order are deterministic per
  instance and reproducible in a session.
- **Parameters** are read at block start through `getRawParameterValue` and cached as
  `std::atomic<float>*`. The per-slot IDs are four `constexpr` arrays of literal strings, each
  element read through an indexed `getRawParameterValue` — that is the form `live_parameter_ids` in
  `audit_bank.py` can parse (scalar `const char*` constants and `const char* x[N] = {...}` used as
  `x[i]`); IDs built by concatenation are invisible to the coverage check.
- **Master volume and pan** are smoothed over 20 ms as per-sample curves advanced once per block,
  with both channels reading the same curve (the Spectral Drift `testOutputGainRampMatchesChannels`
  lesson). Pan is **constant-power** (`cos/sin`), −3.01 dB at centre, documented in the manual; the
  test checks L² + R² invariance rather than a centre gain.
- **Denormals**: `juce::ScopedNoDenormals` at the top of `processBlock` (six of the seven existing
  plugins do this).
- **UI snapshots**: atomic per-slot playhead (0..1 over the fresh span), active flags and missing
  flags, plus a beat position; the editor reads them at 60 Hz.
- **State**: `getStateInformation` / `setStateInformation` via `SuiteState` (version 1), including
  the four `loopNPath` attributes and the `presetSelection` property. `StateHolder` is implemented
  from the start; the host program virtuals are gated by `SUITE_PRESET_BANK_AS_PROGRAMS` (program 0 =
  Init, 1..15 = the bank, append-only). `applyPresetState` runs `SuiteState::read` with
  `resetMissing = true`, then `applyLoopsFromState` (reading the **incoming** tree), and resets
  `currentProgramIndex` on `LoadResult::loaded`.

## Factory loops and presets

### Embedded loop library (12 WAVs)

`tools/cyclical_samples.py` (standard library only, one deterministic recipe per name, seeded by the
name) writes 48 kHz mono 16-bit loops, **exactly 2.000 s each (one bar at 120 BPM)**, to
`plugins/Cyclical/Resources/samples/<name>_4k.wav` (~2.3 MB total; list all 12 in `ASSETS`).
Exact bar length matters: the double-speed lap test and the one-bar quantise presets assume it, and
the engine keeps the source rate rather than resampling.

| Names | Character |
|---|---|
| `kick`, `hats`, `snare`, `perc` | One-bar drum elements |
| `bass`, `chord`, `arp` | One-bar tonal figures |
| `texture`, `drone` | One–two-bar pads |
| `bells` | One-bar bell pattern |
| `vox` | One-bar formant chop |
| `noise` | One-bar filtered noise sweep |

INIT installs `kick`, `hats`, `bass`, `chord` into slots 1–4, so a fresh instance makes sound on the
four keys without loading anything.

## Testing strategy

New test functions and files; every test file starts with `#undef NDEBUG`. Reuse
`tests/common/PluginTestUtils.h` (`checkParameterIds`, `checkRange`, `checkStateRoundTrip`,
`paintComponent`, `countChangedPixels`, `testRenderBaseline`) rather than new helpers.

### `CoreDSPTests` (`modules/core_dsp/tests/DSPTests.cpp`, +8 functions)

1. `testLoopDoubleSpeedLapsTwicePerBar` — the idea 2.10 first step: a one-bar region at speed 2 over
   one bar of output traverses the source twice; the second traversal equals the first (crossfade 0).
2. `testLoopRegionBoundsAndClamping` — `regionFrames` resolves start/length inside the buffer,
   including `Start + Length > 100` and a region at the buffer edge; no read outside the region.
3. `testLoopReverseIsTheMirror` — reverse output equals the reversed forward region, at `X = 0` and
   at `X > 0` (the pre-rolls are mirrored).
4. `testPingPongReflectsAtBounds` — direction flips at both ends, the boundary sample is not
   repeated, no sample outside the region, and the sequence is a palindrome across the turn.
5. `testPingRandomIsPerTriggerAndBounded` — same seed → same turn points; different seeds differ; the
   points are constant for the voice and lie inside the region; **the rate is identical with the
   random on and off** (the regression that stops a detuned retrigger); `Ping Rand` off → plain
   bounds.
6. `testCrossfadeSeamContinuity` — two full cycles at 0 ms and at 50 ms. 0 ms is a bit-exact hard
   wrap. At 50 ms the test samples **across the wrap** (`end → start + X`) and asserts the
   sample-to-sample delta is within the source's own maximum delta, with the cycle RMS within
   ±1 dB (correlated fixture; the −3 dB uncorrelated dip is documented, not asserted).
7. `testGranularIsDeterministicAndWindowed` — same seed → identical output; the first grain starts at
   `start`; grains stay inside the region and wrap within it; no step at grain boundaries.
8. `testVoiceLifecycleGateLatchAndRetrigger` — Gate releases on note-off; Latch ignores it; a
   retrigger produces exactly one audible voice plus one fading tail (≤2 renders), and the tail
   retires within 2 ms.

### `CyclicalTests` (`plugins/Cyclical/tests/PluginTests.cpp`, ~20 functions)

- `checkParameterIds(…, 35)`; `checkRange` for every parameter including choices, bools and defaults;
  `processor.getParameters().size() == 35`.
- State round trip with all 35 off default (bools use the suite's
  `dynamic_cast<AudioParameterBool*> ? 1.0f : 0.73f` pattern); a `suiteStateVersion 99` refusal; an
  additive/minimal state loads with the rest at defaults; `loopNPath` and `presetSelection` survive.
- MIDI map: 60–63 trigger slots 1–4; 59/64 do nothing; four notes together produce all four loops
  (energy above one slot); a retrigger on the same key does not stack.
- Gate vs Latch note-off; default state with no notes produces **exact silence**; latency is 0; tail
  length is 2.0.
- **Channel width**: `processBlock` with a **1-channel** buffer (what the host test passes an
  instrument) produces finite non-zero output and never reads past the buffer; with 2 channels the
  pan separates L/R; a mono source feeds both channels identically at pan 0.
- Quantise: at 120 BPM a trigger inside a 16th step starts on the next grid sample; `swing` moves odd
  grid points by `swingBeats`; Off starts immediately; a Gate tap shorter than the step sounds
  nothing (pending cancel); a second trigger replaces the pending one.
- Loop loading: all four embedded defaults resolve at construction; a missing `loop2Path` sets
  `isLoopMissing(1)` while slot 1 keeps playing; async load clears `hasPendingLoopLoad()` after the
  message loop pumps; two rapid loads keep the latest (generation stamp); a load during a sounding
  voice does not crash (retirement queue).
- Affinity: `Speed` disabled while `Grain` is on; `Ping Rand` disabled outside Ping-Pong; both still
  visible.
- Editor: both pages paint, knobs and pills are on the right page (no control visible on both), the
  preset bar is in the component tree (R12), the gear button is in the component tree and sits right
  of the bar without overlapping it (R13), the About dialog opens and paints, the Settings dialog
  opens and closes, and the render test writes the three views.
- Preset selection restore (plan 09 pattern) and the host program virtuals under the flag.

### `CyclicalPresetTests` (`modules/suite_presets/factory_bank/tests/CyclicalPresetTests.cpp`)

The full shared battery — Sgraffito runs ten helpers and this plugin should too:
`runBankShape<CyclicalProcessor>("Cyclical", 15)` (**the 15 is mandatory**: the default `minPresets`
is 25 and would assert), `runBankRanges`, `runBankNotDefault`, `runApplyMatchesFile`,

## Risks and mitigations

- **Loop-seam clicks** → pre-roll crossfade (resume at `start + X`), 5 ms default; continuity test at
  0 and 50 ms sampling **across** the wrap.
- **Ping-pong random detuning** → turn points randomised, rate untouched; test compares rate with
  the random on and off.
- **Ping-pong random leaking mid-voice** → drawn once per trigger from a hash; test.
- **Granular non-reproducibility** → hash of `(triggerSeed, grainIndex)`; no RNG state in the voice.
- **Sample swap use-after-free** → two-generation retirement queue, generation stamp, lifetime token,
  voice captures its source at `start()` (the Sgraffito/plan 07/plan 09 machinery, reused
  deliberately).
- **Quantise drift** → absolute beat grid, pending sample times, bounded pending list; test at
  120 BPM and with swing.
- **Voice overlap on retrigger** → two voices per slot (active + fading tail), bounded at two; test
  asserts ≤2 renders and tail retirement.
- **Instrument with no input** → the host test passes a **mono** buffer; the channel rule and the
  1-channel plugin test cover it before the host entry exists.
- **Bank tooling** → four edit sites (`preset_data`, two `build_bank` functions, audit); the
  `embeddedLoops` test catches a resource-name typo.
- **Embedded footprint** → ~2.3 MB of mono 16-bit loops; measured in Phase 4.
