## 1. The finding

### 1.1 Summary

The preset bar is not placed in the header band. All three editors compute its bounds from a
rectangle that has already had the header/title strip removed, so the bar lands in the content
area (over the spectrum / groups) or, for Micro-Timing Chaos, deep inside the content area.

### 1.2 Evidence (code as found)

- Spectral Drift — `plugins/SpectralDrift/Source/PluginEditor.cpp:246-257` (`resized`):
  ```cpp
  auto area = getLocalBounds().reduced (16);
  area.removeFromTop (headerHeight);
  const int barWidth = 300;
  const int barHeight = presetBar != nullptr ? presetBar->getPreferredHeight() : 0;
  if (barHeight > 0)
      presetBar->setBounds (area.removeFromRight (barWidth).withHeight (barHeight)
                              .withY (area.getCentreY() - barHeight / 2));
  ```
  `area` is the content area (top already removed). The bar is therefore centred on the content
  area and drawn over the sound page.

- Dynamic Saturation — `plugins/DynamicSaturation/Source/PluginEditor.cpp:229-249` (`resized`):
  identical pattern; `area` is the content area after `removeFromTop (headerHeight)`.

- Micro-Timing Chaos — `plugins/MicroTimingChaos/Source/PluginEditor.cpp:494-504` (`resized`):
  ```cpp
  presetBar->setBounds (getLocalBounds().removeFromTop (titleBandHeight).removeFromRight (barWidth)
                          .withHeight (barHeight)
                          .withY ((getLocalBounds().removeFromTop (titleBandHeight).getCentreY()
                                   - barHeight / 2)));
  ```
  The `withY` value comes from the centre of a rectangle that has already had the title band
  stripped off, so it points into the content area.

### 1.3 Why it is a bug

`juce::Rectangle::getCentreY()` is `pos.y + h / 2` and `withY(newY)` only rewrites the Y origin,
so centering on a rectangle that starts *below* the header yields a bar below the header. The bar
therefore overlaps the first content group in SD and DS, and renders at Y≈713..747 in MTC
(design height 1400, title band 60) instead of inside the title band.

This contradicts:
- plan `docs/plans/03_presets.md` §3.2 ("Bar 300x30 right-aligned in the header" / "Bar 360x34 at
  design scale, right-aligned in the title band"), and
- the restructure decision that the bar ships in every build and reserves its space via
  `getPreferredHeight() > 0`.

The public build is therefore **not** layout-identical to the pre-preset layout, and the plan's
own gate for phase 2 ("editors pixel-identical with Pro off") was never re-verified after the bar
became public.

## 2. Fix

### 2.1 Spectral Drift — `SpectralDriftEditor::resized`

Replace the content-area-based computation with an explicit header rect:

```cpp
auto headerArea = getLocalBounds().removeFromTop (headerHeight);
const int barWidth = 300;
const int barHeight = presetBar != nullptr ? presetBar->getPreferredHeight() : 0;
if (barHeight > 0)
    presetBar->setBounds (headerArea.removeFromRight (barWidth).withHeight (barHeight)
                            .withY (headerArea.getCentreY() - barHeight / 2));
```

`headerArea` is the band `[0, headerHeight)`; `removeFromRight` keeps its Y; `withHeight`/`withY`
then centre the bar in the band. Expected bar bounds: Y = `headerHeight/2 - barHeight/2` = 5..35
for the 40 px header and a 30 px bar.

### 2.2 Dynamic Saturation — `DynamicSaturationEditor::resized`

Same change with `headerHeight` (40) and `barWidth`/`barHeight` (300/30).

### 2.3 Micro-Timing Chaos — `MicroTimingChaosEditor::resized`

Use a title-band rect for both the removal and the centre:

```cpp
auto titleBand = getLocalBounds().removeFromTop (titleBandHeight);
const int barWidth = 360;
const int barHeight = 34;
if (presetBar != nullptr && presetBar->getPreferredHeight() > 0)
    presetBar->setBounds (titleBand.removeFromRight (barWidth).withHeight (barHeight)
                            .withY (titleBand.getCentreY() - barHeight / 2));
```

Expected bar bounds inside the 60 px title band: Y = 60/2 - 34/2 = 13..47 (design units; 22..34 at
the window's 2/3 scale).

### 2.4 General

- Keep the `getPreferredHeight() > 0` gate so the public build reserves nothing.
- Keep the existing `onPresetLoaded` repaint wiring unchanged.
- No change to editor sizes, `setResizeLimits`, or the FFT info line.
