## Executive Summary

Transform two "first-pass" plugins into creative instruments:

- **MidiEffect**: from an instant chord-on-note tool to a chord/arp engine with a step clock, gate, velocity curve and octave spread.
- **StereoTool**: from a static width/drive tool to a characterful stereo processor with a selectable saturation character, one transient follower, mid/side focus and a bypassable side filter.

Both add **8 parameters each** (the review's target): MidiEffect 6 → **14**, StereoTool 3 → **11**, plus `Scattered` appended to the existing `arpId`. Both gain the `PresetBar` through the real `StateHolder` seam and ship **15 factory presets each**. Modulation (`SuiteModulation::Router`) stays deferred; both CMake files already pass `MODULATION`.

## Plugin 1: MidiEffect — "The Chord/Arp Engine"

### Current state (verified)

Source: `plugins/MidiEffect/Source/PluginProcessor.cpp`.

- **6 parameters**: `rootId`, `scaleId`, `chordId`, `arpId`, `octaveId`, `velocityId`.
- **Behaviour**: on note-on it quantises to the scale, builds a chord, orders it by `arpId`, and fires all notes at once with `message.getFloatVelocity() * velocityScale`. On note-off it releases the held chord; a retrigger releases the previous chord first.
- **State version**: 1. **Buses**: stereo in/out, audio passes through untouched.
- **CMake**: `IS_SYNTH IS_MIDI_EFFECT NEEDS_MIDI_INPUT`, `MODULATION` already passed.

### Existing parameters (verbatim from code — do not rename or reorder)

| ID | Name | Choices / range | Default |
|---|---|---|---|
| `rootId` | Root Note | 24–84 (int), shown `C4 (60)` | 60 |
| `scaleId` | Scale | Chromatic, Major, Minor, Minor Pentatonic, Dorian, Whole Tone | Minor (index 2) |
| `chordId` | Chord Quality | Major, Minor, Dim, Aug, Sus2, Sus4, Minor 7, Major 7 | Major (index 0) |
| `arpId` | Arp Pattern | Up, Down, Alternate, Random, **Scattered** (append-only) | Up (index 0) |
| `octaveId` | Octave | int −2…+2 (× 12 semitones) | 0 |
| `velocityId` | Velocity | 0–150 % | 100 % |

`Scattered` is appended to `arpId`, so saved indices 0–3 keep their meaning.

### New parameters (8 → total 14)

| ID | Name | Type | Choices / range | Default | Notes |
|---|---|---|---|---|---|
| `arpMode` | Mode | Choice | Chord, Arp | **Chord** | Chord = exactly the current instant-chord path; Arp = step clock. Default keeps sessions and output unchanged. |
| `stepRate` | Step Rate | Choice | 1/8, 1/8T, 1/16, 1/16T, 1/32 | 1/16 | Step duration; `T` = triplet. |
| `hostSync` | Host Sync | Choice | Off, On | Off | On uses host PPQ + tempo; Off uses `tempo`. |
| `tempo` | Tempo | Float | 40–240 BPM | 120 | Only when `hostSync` is Off. |
| `gateLength` | Gate Length | Float | 10–100 % | 60 % | Note length as a share of the step. |
| `velocityCurve` | Velocity Curve | Choice | Flat, Linear, Exponential, Random | **Flat** | Per-step shape in Arp mode. Flat keeps default velocity uniform. |
| `velocityDirection` | Velocity Direction | Choice | Ascending, Descending | Descending | Applies to Linear/Exponential. |
| `octaveSpread` | Octave Spread | Float | −1…+1 | 0 | Spreads chord tones across octaves. |

The arp is fixed at **8 steps** (the owner's decision), so no step-count parameter is needed. `Random` velocity is deterministic — a hash of (note, step, cycle), the MicroTimingChaos approach — so it needs no seed and is testable.

### Implementation notes

**Chord mode is a hard compatibility requirement.** `arpMode == Chord` runs the existing block verbatim (quantise → chord → `orderArp` → fire with per-note velocity × `velocityId`). `arpMode == Arp` adds the clock path; no existing parameter changes meaning.

**Step clock.** Reuse `CoreDSP::Sequencer` helpers where they fit; otherwise a small clock of the same shape. Each block: advance the beat position (`hostSync` ? host PPQ : `numSamples / samplesPerBeat` from `tempo`), fire every step whose grid time falls in the block, schedule note-on at its grid sample, note-off at note-on + `gateLength × step`. Eight steps cycle through the ordered chord notes.

**Note lifecycle.**
- Note-on in Arp mode: build the chord, store it per key, start at step 0.
- A retrigger before the previous note-off cuts the previous chord's notes first (the existing rule).
- Note-off: release all sounding and pending notes for that key immediately (truncate), matching today's release-on-note-off.

**Velocity.** `finalVelocity = incomingVelocity × velocityId × curveValue(step)`. In Chord mode `curveValue` is 1 (today's behaviour). Flat = 1; Linear = lerp(0.2, 1, t), direction-reversed; Exponential = `0.2 + 0.8·(1−t)²` or its reverse; Random = hash → [0.2, 1].

**Latency.** Report a **fixed 50 ms** (`setLatencySamples` in `prepareToPlay`), matching MicroTimingChaos. The value never changes with rate or gate, so host delay compensation stays stable.

## Plugin 2: StereoTool — "The Character Stereo Processor"

### Current state (verified)

Source: `plugins/StereoTool/Source/PluginProcessor.cpp`, engine `modules/core_dsp/include/StereoEngine.h`.

- **3 parameters**: `widthId`, `driveId`, `mixId`.
- **Behaviour**: mid/side encode → optional `CoreDSP::Stereo::saturate` on M and S → side gain → decode → dry/wet mix. An **identity early-return** exists (`satAmount == 0 && cleanGain == 1 && sideGain == 1 && mix == 1`), which keeps the defaults bit-exact.
- **State version**: 1. **Buses**: stereo in/out.
- **CMake**: `MODULATION` already passed.

### Existing parameters (verbatim from code and tests — do not change)

| ID | Name | Range | Default |
|---|---|---|---|
| `widthId` | Width | −100…+100 % | 0 % |
| `driveId` | Drive | **−24…+24 dB** | **0 dB** |
| `mixId` | Mix | 0–100 % | 100 % |

### New parameters (8 → total 11)

| ID | Name | Type | Choices / range | Default | Notes |
|---|---|---|---|---|---|
| `character` | Character | Choice | Tube, Tape, Diode, Console, Clip | Tube | **Tube is the current `saturate()` exactly.** Replaces the old curve + drive-mode pair. |
| `transientAttack` | Transient Attack | Float (log) | 1–200 ms | 5 ms | One follower; inert while `transientAmount == 0`. |
| `transientRelease` | Transient Release | Float (log) | 20–2000 ms | 150 ms | Same follower. |
| `transientAmount` | Transient Amount | Float | 0–100 % | **0 %** | 0 = follower bypassed (neutral). |
| `transientTarget` | Transient Target | Choice | Width, Drive, Both | Both | What the follower moves. |
| `midFocus` | Mid Focus | Float | −100…+100 % | 0 % | `midGain = 1+f`, `sideGain = 1−f`. |
| `sideFilter` | Side Filter | Choice | Off, High Pass, Low Pass, Band Pass | **Off** | Off = true bypass (default neutral). |
| `sideCrossover` | Side Crossover | Float (log) | 20–8000 Hz | 200 Hz | Only active when `sideFilter != Off`. |

No second drive control: `driveId` is the only drive. There is one follower (not a transient pair plus a width pair). The filter is one control plus its corner.

### Implementation notes

**Character shapers.** Keep `CoreDSP::Stereo::saturate()` untouched (its CoreDSP tests and default output depend on it). Add `CoreDSP::Stereo::saturateCharacter(x, amount, gain, character)`:
- Tube = the existing `saturate(x, amount, gain)` exactly (bit-identical at default).
- Tape = symmetric cubic soft clip `1.5·(y − y³/3)` on the driven, clamped input.
- Diode = exponential for positive excursions, tighter knee for negative.
- Console = gentler tanh blend (lower initial slope).
- Clip = hard clip at ±0.9.

**One transient follower.** A `CoreDSP::Saturation::EnvelopeFollower` (attack/release) over the max of the two channels (linked, as DynamicSaturation does). `transientAmount` scales the follower's effect: at 0 the follower is not applied and the path is the static settings. `transientTarget` selects Width, Drive, or Both — so there is no second width-envelope pair.

**Mid focus.** `f = midFocus/100`; apply `m *= (1+f)`, `s *= (1−f)` after the shaper, before decode. Negative `f` boosts side energy (can widen mono-incompatible content); document that in the README.

**Side filter.** A `juce::dsp::StateVariableTPTFilter` (or one-pole) on `s` only, when `sideFilter != Off`. `sideCrossover` sets the corner. Off = no filter node runs.

**Default transparency (must be proven).** Extend the existing identity early-return to require every new parameter neutral: `character == Tube && transientAmount == 0 && midFocus == 0 && sideFilter == Off`. Add a test that renders the default output and asserts it is bit-identical to the committed build.

## Shared infrastructure

### `StateHolder` — exact interface

Reproduced from `modules/suite_presets/include/SuitePresets.h` (do not paraphrase):

```cpp
virtual ~StateHolder() = default;
virtual juce::String getPresetPluginId() const = 0;                 // "MidiEffect", "StereoTool"
virtual int getPresetStateVersion() const = 0;                      // SuiteState version
virtual juce::AudioProcessorValueTreeState& getPresetStateTree() = 0;
virtual void applyPresetState (const juce::ValueTree&) = 0;         // message thread only
virtual PresetSelection getPresetSelection() const { return {}; }   // non-pure, default body
virtual void setPresetSelection (const PresetSelection&) {}         // non-pure, default body
```

Notes:
- `getPresetStateTree()` returns the **APVTS reference**, not a `ValueTree`.
- The selection pair is **not** pure virtual; override it to persist identity.
- `applyPresetState` runs the tree through `SuiteState::read` with `resetMissing = true` (AGENTS.md §5.5). A delta preset materialises into full state at load.
- The identity travels as the additive `presetSelection` property on `apvts.state` (`"factory:<i>"` / `"user:<path>"`); restore it in `setStateInformation` and reset it on `LoadResult::loaded`.

### `PresetBar` — exact usage

```cpp
PresetBar (StateHolder& holder, juce::Colour accent);
int getPreferredHeight() const noexcept;   // 30
void selectPreset (int factoryIndex);
int  getNumFactoryPresets() const noexcept;
std::function<void()> onPresetLoaded;
```

- The bar **ships in every build**; with `SUITE_PRESET_BANK=0` it reports height 0 and the factory list is empty. It is not "absent".
- Construct it with `(*this, accentColour)` where `*this` is the processor (which implements `StateHolder`). No manual `applyPresetState` wiring: the bar calls the holder.
- Place it flat in the header (no fill/border, plan 05.1).

## Risks and mitigations

- **Step-clock drift** → derive everything from the beat grid, never accumulate per block; reuse `CoreDSP::Sequencer` maths. Test at 40/120/240 BPM.
- **Default-transparency regression** → MidiEffect defaults to `arpMode = Chord`; StereoTool extends the identity early-return; both get a bit-identical output test.
- **Character shapers all sounding alike** → A/B each at the same drive; assert measurable difference.
- **Random velocity non-reproducibility** → hash (note, step, cycle); no seed parameter; deterministic test.
- **Coverage check missing a parameter** → every new ID is a header constant and cached with `getRawParameterValue`; run `audit_bank.py`.
- **Preset equals default** → every preset uses `arpMode = Arp` (MidiEffect) or changes character/drive (StereoTool); audit enforces it.
