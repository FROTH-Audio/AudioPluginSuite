## 2. Phases

### Phase 0 — Probes first (the house rule)
1. **The routed transforms**: script a probe — sine LFO → routing at amount 100, Invert on:
   the routed offset must be the negated waveform (the existing test asserts this; re-run).
   The **scope curve** is the real target: render a plugin editor with a transform set and
   count changed pixels between the scope with and without Invert — it will not change
   today (the fix lands in Phase 1 and the probe becomes the regression test).
2. **The Cyclical filter**: render two probes — a bright loop (full-scale harmonics) with
   slot 1 LP + Cutoff 300 Hz against the identity, and an HP sweep. The output must
   differ sample-wise and stay bounded. If it already differs, the finding was the
   dropdown size/affinity, not the DSP — record either way.
3. **The Cyclical A/R**: a probe with Attack 800 ms / Release 2000 ms against the
   1 ms/5 ms defaults on a triggered loop: the level envelope must follow (the probe
   compares the first 100 ms RMS after the trigger and after the release).
4. **The transform parameters in a DAW**: after any fix, remind the owner that every
   modulation plugin's parameter count changed in plan 17 (+12) — a stale DAW cache
   hides the new parameters from host automation (Ableton rescan, AGENTS §10).

### Phase 1 — The transforms: fix the scope, knobs with labels and room
Files: `modules/suite_modulation` (router, scope, panel), tests, the six editors' renders.
1. **Router**: a public `transformedLfoValue (int lfo, double cycles) const` that builds
   the LfoTransforms from the cached parameters (the same values `lfoOutputAt` uses), calls
   `CoreDSP::Modulation::lfoValue (shape, cycles, seed, transforms)`, applies the Offset
   and clamps — the one path the scope and the routing share.
2. **Scope**: the one-cycle curve and `curveValue` sample `router.transformedLfoValue`
   instead of the raw `lfoValue` (the scrolling histories already record the transformed
   output). The drawing stays byte-identical when every transform is neutral — the
   existing renders are the regression baseline.
3. **Small knobs for the transform controls** (owner addition, 2026-11-24): the four mini
   sliders become **rotary knobs at the suite's 40 px diameter** — plain
   `SuiteUI::LabelledSlider`s, so this uses the existing widget untouched (no R1 change:
   `knobDiameter` already *is* 40 px) and brings the full R2 idiom — caption above
   (QUANTISE / SMOOTH / PULSE / SKEW, the labels the owner asked for), value box below.
   The four knobs sit in one `knobRowHeight` row, the **INVERT / RECT** pills join the
   row beside them (or a pill row above — the render decides), and `lfoBlockHeight`
   grows to fit (measure from the layout; the render decides). The panel's preferred
   height grows with it, so the six MOD-page windows re-measure (SD at 750 is the tight
   one).
4. **Tests**: a scope-curve regression (the drawn pixels change when a transform moves —
   the Phase 0 probe promoted), and the panel's preferred-height rule re-checked. Renders
   of all six MOD pages under `docs/manuals` (R11) with the crop boxes re-measured.
