## 2. Phases

### Phase 1 — Trigger modes, per-slot notes, tempo parameters

Files: `plugins/Cyclical/Source/PluginProcessor.{h,cpp}`, `PluginEditor.{h,cpp}`,
`tests/PluginTests.cpp`. Parameter and state additions are **additive**: state version stays 1
(`resetMissing` restores defaults for absent IDs; the additive load is already tested) and no
existing index moves.

1. **Toggle trigger mode**: `triggerMode` gains a third choice, **Toggle** (append-only, index 2).
   Press starts looped playback of the slot region (the region loops until stopped); the next
   press stops it. A Toggle start follows today's trigger path (scheduled on the next quantise
   grid point when Quantize is on); a Toggle stop is **immediate** on the second press, never
   delayed to the grid. Latch (one-shot) and Gate (plays while held) keep their indices and meaning.
   Slot state gains `toggledOn`; transport stop and relocate clear it.
2. **Per-slot note**: `slotNNote` ("Note", int 24–96, defaults 60/61/62/63 = today's fixed map),
   appended after `slotNVelocity`. The fixed `firstSlotNote` mapping is replaced by reading each
   slot's note. Cyclical has no UI-originated triggers today, so the note-off guarantee of plan 13
   Phase 7 does not apply. If a UI trigger is ever added, that rule applies.
3. **Global tempo**: `tempo` ("Tempo", 40–240 BPM, default 120) and `sync` ("Host Sync", off/on),
   appended after `crossfadeLength`, the MTC pattern. Beat clock: host PPQ + tempo when synced with
   a playhead; `tempo` otherwise; 120 with no transport, as today.
4. Tests: toggle mode (press → loops; second press → stops immediately, even with Quantize on;
   note-off does not stop it), note remap
   (slot 0 moved to 72 → only 72 triggers slot 0), additive state load with the new IDs absent,
   `checkParameterIds` 35 → **41** (+tempo, +sync, +4 Note), state round trip.

### Phase 2 — Loop sync and the Speed rule

Files: `plugins/Cyclical/Source/PluginProcessor.{h,cpp}`, `PluginEditor.{h,cpp}`,
`modules/core_dsp/include/LoopEngine.h` (only if the rate maths belongs there), `tests/PluginTests.cpp`.

1. **Per-slot `slotNBeats`** ("Beats", int 1–16, default 4): the musical length of the **whole
   loaded loop**. With sync on:
   `rate = loopSeconds / (slotNBeats × beatSeconds)`, so the whole loop plays in exactly
   `slotNBeats` beats. Start and Length choose which part of the loop plays; they do not change
   the rate. Loop duration comes from the loaded sample (frames / sampleRate).
2. **Speed is inactive while Host Sync is on** (G-B). Dimmed, not hidden, with the same
   mode-affinity mechanism Sgraffito uses (`updateModeAffinity`, AGENTS §13). The manual says
   so. With sync off, Speed works exactly as today.
3. With sync off, behaviour is exactly today's: the rate is `slotNSpeed` × the sample-rate ratio.
4. A chopped slot ignores global sync (owner decision; Phase 3 implements the chop side). Phase 2
   states the rule here so the sync tests cover it from the start.
5. Tests: the whole loop plays in `slotNBeats` beats at the given BPM, for two different Start and
   Length settings (the rate must not change); Speed has no effect while synced; sync off
   unchanged (the existing rate tests still pass); `checkParameterIds` 41 → **45** (+4 Beats).

### Phase 3 — Chop mode with variable slice length

Files: `plugins/Cyclical/Source/PluginProcessor.{h,cpp}`, `LoopWaveformView.{h,cpp}` (Phase 4 for
drawing), `tests/PluginTests.cpp`, `tools/preset_data.py` (Phase 6).

1. **Per-slot chop parameters**, appended after `slotNBeats`:
   - `slotNChop` ("Chop", bool, off);
   - `slotNSlices` ("Slices", int 2–16, default 8);
   - `slotNSliceLength` ("Slice Length", float −100…+100 %, default 0 %) (G-A). **0 % = equal
     slices.** Positive values lengthen the slices toward the end of the region, negative values
     lengthen the slices at the start. Boundaries are `b_i = (i/S)^e` with `e = 2^(+2·v)` and
     `v = Slice Length / 100 %`: with `e > 1` (positive v) the derivative `e·x^(e−1)` grows with
     x, so the late slices are longer; with `e < 1` the early ones are. The boundaries are
     strictly increasing, `b_0 = 0`, `b_S = 1`, and
     `v = 0` gives exactly the equal split.
2. **Sync is disabled for a chopped slot** (owner decision). A chopped slot ignores global Host
   Sync and its own Beats value; its Beats knob is dimmed. Unchopped slots keep Phase 2's sync.
   Global `tempo` still drives the beat clock for the other slots.
3. **DSP**: no new traversal engine. Slice k is the region between `b_k` and `b_{k+1}` of the
   slot's region, fed into the existing `Region {startFrame, lengthFrames}` with the slot's
   speed, direction and crossfade settings intact. Frame counts round by largest remainder, so
   the per-slice `regionFrames` sum exactly to the region length and the last boundary lands on
   the region end. The LoopEngine's seam crossfade already clamps
   `X = min (crossfadeFrames, lengthFrames/2)`, so short slices do not fold.
4. **Granular inside a slice is allowed** (G-D). The grain (80 ms) is longer than a short slice may
   be, so the grain wraps within the slice like region playback does (AGENTS §5 grain rule). The
   manual says that very short slices sound grainy.
5. **Key mapping**: in chop mode the slot's trigger is replaced: key `slotNNote + k` triggers slice
   k, for k in 0…slices−1. Non-chopped slots keep the single trigger at `slotNNote`. Overlaps with
   other slots' keys are accepted (§1).
6. Tests: boundaries (`b_0 = 0`, `b_S = 1`, strictly increasing; `v = 0` equals the equal split;
   `v > 0` lengthens the late slices; `v < 0` the early ones); per-slice `regionFrames` sum to the
   region length; key→slice mapping (base note + k, out-of-range keys ignored); chop off unchanged;
   a chopped slot's rate does not change when Host Sync or Tempo changes; granular inside a slice
   produces output and stays inside the slice. `checkParameterIds` 45 → **57** (+4 Chop, +4 Slices,
   +4 Slice Length).

### Phase 4 — SLOTS page layout and window size (G-C)

`build/renders/`.

1. Second knob row per card: **Note**, **Beats**, **Slices**, **Slice Length** (the four knobs use

4. Dimming (never hidden, the Sgraffito mode-affinity rule): Beats is dimmed while the slot is

   Slices and Slice Length are dimmed while chop is off.
5. Tests: an editor test asserts the card's knob row count (two rows of four), the window size
   (1000 px wide), and that the dimming rules hold for each combination of Chop and Host Sync.
   Renders of the SLOTS page before and after (R7/R9); the before render is taken in Phase 0.

## 3. Open points and risks

| Item | Note |
|---|---|
| Window size (G-C) | Width 1000 and the height are owner-approved after the Phase 4 renders. Present the measured number; do not resize without approval |
| Cyclical sync rate jumps | Changing `slotNBeats`, `tempo` or toggling sync mid-loop rescales the rate and the read position jumps. Mitigation: apply the new rate from the next region pass, or crossfade the seam. Implementer decides and tests the audible result |
