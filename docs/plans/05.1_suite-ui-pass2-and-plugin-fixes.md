(`05_suite-ui-rework.md`) and its R1–R10 rules in AGENTS.md section 7 are the baseline this

| Sgraffito windows | The TEXTURE page overflows 880×640 (5 knob rows + selector need ~590 px of content, only ~522 available) — that clipped the late rows and produced the small "Swell Time" knob. Fix by adding the missing MOD page and re-grouping, not by stretching the window |
| Sgraffito modulation | The processor has the full `SuiteModulation::Router` (24 targets); the editor never built the panel. Add the MOD page with `ModulationPanel` + `ControlDisplay`, exactly like SD/DS |
| Sgraffito sound bug | Investigate with probes before touching DSP: render the embedded sample through each mode and each suspect parameter, compare RMS/spectrum, and fix what is provably dead. No blind parameter changes |
| Panning (DS) | New parameter, appended last (ID `pan`, −100 % left to +100 % right, default centre, **balance law** after the output gain: centre is unity in both channels, hard pan silences the opposite channel — equal-power would attenuate the centre by 3 dB and change every existing level and test). Follows AGENTS section 9 "Adding a parameter": `numControls` 47 → 48, plugin tests, presets unaffected (absent IDs reset), README table |
| Keyboard (Sgraffito) | New `SuiteUI`-style strip at the bottom of every page; the editor pushes note on/off into a small lock-free queue the processor drains in `processBlock` (the audio thread never locks, AGENTS section 7) |
| Grouping (SD, DS, Sgraffito) | Re-arrange rows so related controls sit together and each row gets a small `textDim` subtitle where the grouping is not obvious; no parameter moves pages except LFO SHAPE (SD) |

### Phase 2 — Micro-Timing Chaos

Files: `plugins/MicroTimingChaos/Source/PluginEditor.{h,cpp}`, `LerpPreview.{h,cpp}`.

1. **Lerp view bug (root cause identified).** `setPage` makes *both* `curveEditor` and
   `lerpPreview` visible on the DRIFT page; the preview is added after the curve, so it
   paints on top — the first DRIFT open shows the preview. Fix: `setPage` respects the lerp
   view state — `curveEditor.setVisible (driftPage && lerpView == 0)`,
   `lerpPreview.setVisible (driftPage && lerpView == 1)`. Add a regression test: build the
   editor, `setPage (1)` only, assert `curveEditor.isVisible()` and `! lerpPreview.isVisible()`.
2. **Transport group.** Reproduce on a fresh build first (the plan 05 after-render shows the
   group on the MOD page). If it is genuinely missing in the owner's build, find the stale
   binary or the visibility/paint fault and fix it; if it does not reproduce, record that
   and close the item with the render as evidence.
3. **DRIFT page relayout** (owner sketch):
   - Left column: the LERP CURVE group takes the full content height; the curve/preview
     view spans the group width; the four lerp knobs (LERP, X, Y, Z) sit *below* the view,
     in one row of four.
   - Right column, width of ATTRACTOR VISUALIZATION: attractor on top, the CHAOS group
     below it (three knobs, smaller cells, no dead space between them).
   - The CHAOS group's bottom edge aligns with the LERP group's bottom edge.
4. **Legend and captions.** Remove the three-colour legend (`X timing / Y pitch & gate /
   Z velocity`) from the preview; relabel the multiplier captions to carry the meaning:
   "TIMING (X MULT)", "PITCH (Y MULT)", "VELOCITY (Z MULT)" — `describe()` texts updated to
   match. If the legend colours are also used inside the preview's traces, keep the traces,
   remove only the caption row.
5. Render SEQUENCE/DRIFT/MOD; the DRIFT render is the acceptance check for 3 and 4.

### Phase 3 — Sgraffito

Files: `plugins/Sgraffito/Source/PluginEditor.{h,cpp}`, `PluginProcessor.{h,cpp}`,
`modules/suite_ui/brand/lockup_sgraffito.png` (regenerated), plus a new keyboard strip.

1. **Preset bar.** Add `SuitePresets::PresetBar` to the editor header exactly like SD/DS/MTC
   (`suite_presets_add_to_target` is already in the CMake chain via `suite_add_plugin`).
   Reserve its width in the header, left of the page selector.
2. **Logo.** The gap between FROTH and Audio in `lockup_sgraffito.png` is wider than in the
   other lockups. Regenerate with `build/brand/lockup_sgraffito.py`: move "Audio" to sit
   right of the FROTH baseline (compare against `lockup_spectral_drift.png` proportions),
   keep the slate accent. Render both lockups side by side for the owner.
3. **Knob consistency = the overflow.** The TEXTURE page needs ~590 px of content in a
   ~522 px window at 880×640, so the late rows clipped and their knobs shrank. Fixed by the
   re-grouping below plus the MOD page; verify every knob renders 40 px after Phase 1.
4. **MOD page (new).** Third page in the selector: `ModulationPanel` (2 LFOs, 6 slots) +
   `ControlDisplay` wired to the processor's `ModTarget` table, `modulationStyle()` in the
   slate accent, `modulation.prepare/computeOffsets/publish/advanceBlock` already run in
   `processBlock` (plan 04 wiring) — only the UI joins. `numControls` unchanged (71).
5. **Re-grouping.** SOUND page: row subtitles "REGION" (span, length), "PITCH" (root, fine,
   glide), "LEVEL" (level, velocity curve, attack, release) — or two rows + the pill row.
   TEXTURE page, grouped and re-flowed to fit: TAPE (tape stop time + curve), MEMORY
   (amount, decay), DRIFT (amount, speed), TIMING (lay back, swing, humanise, shuffle seed),
   GHOST (on, threshold, level, delay), CLOUD (slice count, grain size, density, spread),
   SWELL (hold, time, crossfade), SURFACE (dust, crackle, wow, flutter). Rows that do not
   fit move to the MOD page next to the panel.
6. **Playable keyboard.** New `SuiteUI::PlayableKeyboardStrip` (white/black keys, mouse
   down/move/up per key, drag glissando) at the very bottom of every page, above the help
   line. The editor owns a `juce::MidiKeyboardState`-free lock-free note queue
   (`SgraffitoProcessor::pushNoteOn/pushNoteOff`, SPSC ring of ~32 events); `processBlock`
   drains it before the host MIDI loop. Keys light while held (the strip tracks its own
   pressed keys). Audio-thread rules: no locks, no allocations.
7. **Sound probe and fixes.** Harness (test executable or a throwaway probe under `build/`):
   render 2 s of the embedded sample at note 60 through each mode (0–3) and each of the
   suspect parameters driven to both extremes (level, memory amount/decay, drift
   amount/speed, dust/crackle/wow/flutter, swell time, grain density), record RMS and
   spectral difference against mode 0 defaults. Anything that does not move the output gets
   a fix and a regression test (the existing plugin-test pattern). The owner's report
   ("nearly always the same") suggests the mode regions are too similar on a short sample —
   check the region maths end to end first.
8. Render both pages + MOD; the knobs-all-40-px check is part of the gallery.

## 3. Risks and traps

- **40 px knobs are small.** The value box (84 px) is wider than the knob; keep the box
  centred on the knob, not the cell, so the pair reads as one control. If the ring is
  unreadable, the decision is LED count, not dot size (the dots are part of the frozen look).
- **Sgraffito audio bug is a report, not a diagnosis.** Phase 3.7 runs before any DSP edit;
  the fix must come with a probe that fails before and passes after.
- **The keyboard queue** is the only new audio-thread surface: SPSC, fixed capacity,
  `std::atomic` indices, overflow drops oldest. No `MidiBuffer` contention with the host
  buffer (drain into a local list, then merge).
- **Panning changes the DS output tests?** Pan at centre is unity (cos 0 = sin 0 = 1 with
  equal-power normalisation) — the existing tests must stay bit-identical at the default.
  Verify with the reconstruction-style probe before committing to the law.
- **The preset bar in Sgraffito** appears in the default build as a 0-height stub
  (`isAvailable()`), so the layout must handle both heights, like SD/DS/MTC already do.
- **MTC DRIFT relayout** moves the chaos group into the right column: the `describe()` help
  texts and the render test must keep working; the plan 02 glyph-flakiness caveat applies.
