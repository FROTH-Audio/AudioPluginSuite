# Plan 05.4: Sgraffito — wire the silent controls to the audio

Written for: the coding agents who carry out the phases, with one owner gate on the control
semantics (Phase 0). Read `AGENTS.md` first; plan 05.1 pass 2 is the baseline — it fixed the
"always sounds the same" bugs (position init, envelope time base, per-sample decay, key pitch,
cloud grains) and left the controls below explicitly unwired (AGENTS §14).

Status: proposed 2026-11-12. Not started.

Purpose: Sgraffito's TEXTURE page has eight controls and one switch that are cached in the
processor but never read by the audio path — turning them does nothing. This plan designs,
implements and regression-tests each of them, following the probe-first pattern that caught
the plan 05.1 sound bugs: a test that fails before and passes after, per control.

Purpose is also honesty about scope: the original plan 04 described these features loosely.
This plan pins down concrete, deterministic semantics — proposed here, owner-gated — because
"a ghost note" or "vinyl dust" is not implementable without decisions.

## 1. Decisions (owner gate in Phase 0)

| Question | Proposal |
|---|---|
| Swing semantics | A sampler has no groove position, so swing applies to **repeated notes of the same key**: successive note-ons of one key alternate straight/swung. Swing 50 % = straight; 75 % delays the swung copy by half a beat at the current tempo (tempo from the routing panel's Host Sync state, 120 BPM default). Implementation via the existing `pendingNotes`/lay-back machinery — swung notes are queued, not allocated directly. Needs a per-key alternation counter (deterministic, reset on note-off) |
| Humanise | Every note-on start gets a deterministic random offset of 0…`humanise` ms (seeded from key + a per-note counter, so tests are repeatable). Applies before the lay-back delay, additive |
| Ghost notes | When `ghostOn` and a note-on's velocity is **below** `ghostThreshold` %, additionally schedule one quieter copy: same region, velocity scaled by `ghostLevel` dB, delayed `ghostDelay` ms, played on the **same key** (the GhostNote struct already carries everything). Ghosts do not retrigger ghosts. Ghosts respect note-off? No — ghosts are one-shot: they play their region once and stop (like the normal one-shot behaviour) |
| Sustain hold | With `sustainHold` on, a note-off does **not** release the voice — it latches. The voice keeps playing its region (one-shot to the region end, as today). The next note-on of the same key releases the latched voice first. Note-off while the switch is already on and the voice is latched: second note-off releases (escape hatch). Implemented via the engine's `noteHeld` flag: `releaseVoice` is skipped for latched voices |
| Swell time / crossfade | `swellTime` (ms) shapes the **swell envelope** of Swell-mode voices: the reverse-playback gain rises over `swellTime` ms (in addition to the normal attack). `swellCrossfade` (ms) replaces the current hard wrap at the region start with a crossfade between the region's last and first `crossfade` samples during the wrap. Applies to Swell mode only |
| Dust | A static, band-limited noise bed, always present, level 0…`dust` % of −24 dBFS, low-passed (the existing `OnePoleFilter` in CoreDSP::Saturation). Independent of voices |
| Crackle | Sparse impulses: deterministic random (seeded LCG, like the modulation seeds) decides per block whether an impulse fires; impulse = short decaying click, level scaled by `crackle` %. Independent of voices |
| Wow / flutter | Per-voice playback-rate modulation: wow = 0.5 Hz LFO, depth up to ±25 cents at 100 %; flutter = 6 Hz, up to ±8 cents at 100 %. Rate multiplier computed per block (not per sample), deterministic from `noteId` seeds. Multiplies into the existing `rate` chain (tape stop, chaos drift) |
| Parameter removals | None. All stay; they become real |
| Presets | After the controls are audible, revisit F1.3's coverage list: the "Tape & Memory", "Ghost" and "Surface" factory presets gain deltas for the newly live controls (small re-authoring, bank order unchanged) |

## 2. Phases

### Phase 0 — Owner gate on the semantics table above

The table in §1 is the design of record. The owner approves it (or amends rows) before code.
Particular ask: Swing's retrigger semantics — if the owner had a different behaviour in mind
(e.g. host-position-based swing), say so now, because everything else is unambiguous.

### Phase 1 — Timing controls: swing and humanise

Files: `plugins/Sgraffito/Source/PluginProcessor.{h,cpp}`.

1. `handleNoteOn` gains the humanise offset (deterministic per note) and the swing decision
   (per-key alternation counter `std::array<std::uint8_t, 128>` reset in `handleNoteOff`).
   Swung notes go through `pendingNotes` with their combined delay (humanise + lay-back +
   swing offset) — the existing lay-back block already fires delayed note-ons, so swing/humanise
   reuse it even when lay-back itself is 0 ms.
2. The lay-back firing block's condition changes from `layBackMs > 0` to "there are pending
   notes" (swing/humanise can queue notes with zero lay-back).
3. Regression tests: render N repeated note-ons of one key at swing 50 vs 75 and compare the
   onset positions (detect via the first non-zero sample after each expected onset); humanise
   with a fixed seed shifts onsets by a known, bounded amount.

### Phase 2 — Ghost notes

Files: `plugins/Sgraffito/Source/PluginProcessor.{h,cpp}`.

1. `handleNoteOn`: when `ghostOn`, velocity below threshold, and a free ghost slot — fill the
   GhostNote (key, ghost velocity from `ghostLevel` dB, region from the shared engine maps as
   the main voice, `delayRemaining` = `ghostDelay` ms in samples).
2. `processBlock`: after the main voices, advance the ghost array — decrement delay, then
   allocate a real voice per active ghost (through `allocateVoice` so stealing/regions stay
   consistent), mark the ghost consumed. Ghosts never spawn ghosts (the spawned voice is a
   normal voice; guard by flag).
3. Note-off releases main and ghost voices of the key (the existing key loop already matches
   by key; ghosts carry the same key so they release too — intended).
4. Regression tests: threshold above/below the ghost condition (ghost fires only below);
   delay timing; `ghostOn` off = no ghost; level relationship (ghost RMS ≈ main RMS scaled
   by the ghostLevel dB factor).

### Phase 3 — Swell shaping and sustain hold

Files: `plugins/Sgraffito/Source/PluginProcessor.{h,cpp}`,
`modules/core_dsp/include/SamplerEngine.h` (only if a helper helps; prefer inline in the
processor like the rest of the mode handling).

1. Sustain hold: `handleNoteOff` skips `releaseVoice` when `sustainHold` is on and the voice
   is held; a `latched` marker per voice (reuse `noteHeld`) makes the second note-off release.
   `handleNoteOn` of the same key releases the latched voice before allocating.
2. Swell envelope: Swell-mode voices gain a shape multiplier rising over `swellTime` ms from
   the note start (separate from attack; multiplies the existing `env`). Implemented inline in
   the per-voice loop from `envStart` and the absolute sample counter.
3. Swell crossfade: at the reverse wrap (position < regionStart → jump to regionEnd), crossfade
   over `swellCrossfade` ms between the tail read and the wrap read (linear equal-power mix),
   instead of the hard jump.
4. Regression tests: latch behaviour (note-off keeps sounding, second note-off stops, retrigger
   releases first); swell envelope rise visible over `swellTime`; wrap crossfade energy
   continuity (no discontinuity spike at the wrap sample).

### Phase 4 — Surface: dust, crackle, wow, flutter

Files: `plugins/Sgraffito/Source/PluginProcessor.{h,cpp}`.

1. A small deterministic noise source in the processor: a 32-bit LCG seeded like the
   modulation seeds (fixed constants, e.g. `0x51A5u`), advanced per block — no allocations,
   audio-thread safe.
2. Dust: per block, `dust` % scales a one-pole low-passed noise add into both output channels
   (post voices, pre level? Decision: post voices and post output gain — it is a "surface"
   like vinyl, so it plays even in silence; document). Implementation detail: OnePoleFilter
   instance per channel, initialised in `prepareToPlay`.
3. Crackle: per block, the LCG decides fire/no-fire (density ∝ `crackle` %); on fire, a short
   decaying impulse (a few samples) into both channels.
4. Wow/flutter: per voice, per block — rate multiplier `2^((wowDepth × sin(2π × 0.5 × t) +
   flutterDepth × sin(2π × 6 × t)) / 1200)` with the depths derived from the parameters and
   the phase seeded per voice (`noteId`), advanced by the block length. Multiplies into the
   existing `rate` chain before the chaos drift.
5. Regression tests: dust/crackle raise the noise floor (RMS above a threshold at 100 %, near
   zero at 0 %); wow/flutter shift the apparent pitch (zero-crossing count changes, like
   `testKeyChangesPitch`); all deterministic across two runs of the same seed.

### Phase 5 — Presets, docs, verification

1. Bank: add deltas for the newly live controls where the existing "Tape & Memory", "Ghost"

## 3. Risks and traps

- **Audio-thread discipline** (juce-plugin rules): all new state is lock-free — no allocation,
  no locks in `processBlock`. The LCG and the per-key counters are plain members; the ghost
  array is a fixed-size member. The keyboard note queue pattern (SPSC) is the template.
- **Determinism for tests**: every new random element (humanise, crackle, wow/flutter phase)
  derives from fixed seeds (key, noteId, the LCG), never from `Random` unseeded time — the
  regression tests must be repeatable.
- **Swing + lay-back interaction**: both feed `pendingNotes`; the combined delay must be
  computed once (humanise + swing offset + lay-back), or swung notes could double-delay.
- **Latched voices and voice stealing**: a latched voice occupies a slot; with 32 voices and
  the keyboard, latching everything can exhaust the pool — `findVoiceToAllocate` steals the
  oldest, which may kill a latched voice. Accepted; document.
- **Ghosts and the one-shot region end**: ghosts inherit the normal region-end release, so a
  long delay + short region means the ghost may silence before the delay elapses. The ghost
  should be allocated *at fire time* (after the delay), so it plays from its own start — the
  delay is in the GhostNote, not in the voice.
- **Dust/crackle in silence**: they play with no voices — intended (vinyl surface), but the
  test `testModesProduceDifferentAudio`-style comparisons must account for the noise floor
  (use a dust/crackle = 0 default in unrelated tests, which the defaults already are).
- **Swell crossfade wrap**: the wrap happens per sample in the reverse branch; the crossfade
  needs the position relative to the region edges — compute per sample, cheap.
- **`envValue` staleness**: the release level reads `voice.envValue` (set only at allocation);
  while wiring sustain hold, check the release level still starts from the audible level
  (plan 05.1 pass 2 fixed the time base; verify with the latch test).
