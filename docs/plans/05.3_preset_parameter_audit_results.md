## 0. Executive summary

The preset system is **internally consistent on the parameter side** (all four plugins' live parameter
sets are covered by the authoring schema, and the bank audit passes), but the **documentation around
the preset system is not in step** with the code, and the **audit has no automated coverage of the
live-parameter ↔ schema comparison** it is meant to perform.

The most material findings:

1. The bank audit passes, and the authoring schema covers all four plugins' live parameters (48 /
   47 / 54 / 71).
2. The prose describing the factory bank is stale in several places (INIT-only narrative vs the
   current 100-preset bank; "always compiled" vs the `SUITE_PRESET_BANK` flag gate).
3. `AGENTS.md` and `README.md` carry outdated preset counts and outdated test counts.
4. No automated check ties the live APVTS parameter IDs to `tools/preset_data.py`'s `SCHEMA`.

### 1.2 Findings

- **F1.1 — No automated live-parameter ↔ schema coverage check.** `tools/audit_bank.py` rejects
  unknown parameter IDs used in preset deltas, but it does not verify that the `SCHEMA` contains every
  parameter the processors expose. A newly added parameter forgotten in `SCHEMA` would silently drop
  out of preset authoring, while `resetMissing` keeps presets loadable. **Recommendation:** add a
  coverage check (audit or bank test) that diffs the live `numControls`/IDs against the schema, or at
  minimum a documented checklist item in `tools/preset_data.py`.
  **Resolved 2026-11-12:** `audit_bank.py` now parses the live parameter IDs from each plugin's
  sources (header constants plus `getRawParameterValue` arguments, the shared Router's parameters
  added when the plugin uses it), cross-checks them against `SCHEMA` in both directions and against
  `numControls`. Verified to catch the exact F1.4 drift when `pan` is removed from the schema.
- **F1.2 (updated 2026-11-12).** The Dynamic Saturation `pan` parameter of plan 05.1 Phase 4.5 **is
  implemented** now: `numControls` 47 → 48, `panId = "pan"`, APVTS `Panning` (−100 % … +100 %, default 0,
  appended last, equal-power law after the output level), editor slider bound, tests updated
  (`checkParameterIds` + `checkRange` include `panId`). The CHANGELOG entry ("a new Panning parameter
  (balance law, appended last) … **48 parameters now**") and the `AGENTS.md` §4.2 table were updated in
  the same change. The owner confirmed the Phase 4.5 scope OK. **However, the preset authoring schema
  (`tools/preset_data.py` → `SCHEMA["DynamicSaturation"]`) still has no `pan` entry**, and
  `README.md` still has no Panning row — the parameter↔preset comparison now has a live gap (see F1.4).
- **F1.3 — Factory-preset coverage (first pass, re-checked 2026-11-12, resolved 2026-11-12).**
  Sparse deltas are by design, but a coverage table shows parameters that no factory preset ever
  moves off default: Spectral Drift `outputGain`; Dynamic Saturation `outputLevel` (and `pan`, since
  removed); Micro-Timing Chaos routing slots `mod2`–`mod6`; Sgraffito creative parameters (`attack`,
  `release`, `tapeStopCurve`, `layBack`, `swing`, `ghostOn`, `ghostLevel`, `grainSize`, `sustainHold`,
  `wow`, `shuffleSeed`, …). **Resolution (2026-11-12, owner ruling):** output levels/gains are never
  authored by factory presets (the user owns the level); the structural LFO/routing slots stay at
  defaults; and Sgraffito gained five new factory presets (Velvet Swing, Ghostly Echo, Held Breath,
  Fine Grained Drift, Slow Attack Tape — bank total now 100, Sgraffito 20) that use the attack and
  release envelopes and showcase the performance controls. The coverage gaps that remain are the
  structural ones above. Verdict: resolved.
- **F1.4 — Live parameter missing from the preset authoring schema.** Re-scan of the project after
  the plan 05.1 Phase 4.5 work (owner-confirmed scope OK) shows the Dynamic Saturation Companion now
  exposes **48** parameters including **`pan`** (`panId`, APVTS "Panning", −100 % … +100 %, default 0,
  **balance law** — unity at centre, hard pan silences the opposite channel; an earlier note said
  "equal-power", that was changed during implementation, see plan 05.1 §1), appended last, but
  `tools/preset_data.py` → `SCHEMA["DynamicSaturation"]` still lists only the 47 pre-pan keys and has no `pan` entry. Consequence: preset deltas cannot address
  `pan`; a future bank preset could not author a pan value; the missing-coverage check of F1.1 would
  not have caught it because the schema drift came together with the live parameter. **Fix:** add `pan`
  to the Dynamic Saturation schema, run `python tools/build_bank.py` + `python tools/audit_bank.py`,
  and review whether any factory preset should use it (default 0 = centre means no delta is required,
  but the schema must know the parameter).
  **Resolved 2026-11-12:** `pan` added to the schema (balance law, −100…+100, default 0), bank
  regenerated (95 presets unchanged in content), audit passes with the new coverage check. No preset
  delta authors `pan` yet (default = centre); preset coverage is F1.3's open decision.
  **Superseded later the same day:** the owner removed the DS `pan` parameter entirely (no hidden
  parameters); the schema entry went with it, and the F1.1 coverage check verified the removal
  stayed in step. The same pass removed Spectral Drift's `driftRate` and `lfoShape` parameters with
  their schema entries — the drift is driven by the routed LFOs now (see plan 05.1 pass 2).
