## [Unreleased]

### Added
- Multiband Saturation (`plugins/MultibandSaturation`, plugin code `Msat`): a seventh plugin, plan 06 idea 2.4's first pass. A two-way Linkwitz-Riley split (`CoreDSP::Multiband::TwoBandSplit`, 24 dB/oct, the low and high bands sum back to the input's magnitude through the crossover's all-pass phase) with the Dynamic Saturation rule per band: each band's drive is pushed by its own envelope follower, shaped by the shared Tube/Tape/Diode curve, and tilted by its own tone control. The band sum is clamped to the rails; drive, tone, mix and output level are smoothed 50 ms. Eleven parameters; the first pass runs at base rate (no oversampling — the plan's oversampling-and-crossover interaction stays an open risk), so 0 samples of latency are reported. Tests: the split's unity in `CoreDSPTests`, plus bounds, mix-0 dry, per-band independence, parameters, state and editor in the plugin.
- Spectral Drift: sidechain-driven spectral ducking (plan 06 idea 2.5, built into the plugin per the owner's decision). A second input bus named *Sidechain* (declared disabled, mono or stereo when a host enables it) feeds a peak follower (5 ms attack, 150 ms release) that ducks one target: **Drift** flattens the routed drift while the sidechain sounds, **Gate** sweeps the gate threshold up so the wet spectrum thins from the bottom. Two appended parameters (`sidechainAmount` 0–100 %, default 0, and `sidechainTarget` Drift/Gate) — the defaults are bit-identical to the committed sound, and the 48-parameter layout keeps every saved index stable. Tests cover the transparent amount-0 case, the drift duck and the gate duck; the VST3 host-load test runs the plugin through the host wrapper with the bus declared.
- Stereo Tool Effect (`plugins/StereoTool`, plugin code `Ster`): a fifth plugin, mid/side width, drive and mix per plan 06 idea 2.9. Its DSP lives in the shared `core_dsp` (`StereoEngine.h`): exactly-lossless mid/side encode/decode, a guarded side gain (width 0 transparent, -100 % mono, +100 % double side) and a drive-style tanh saturator whose 0 dB is transparent (negative Drive is clean gain reduction). Transparent at the defaults (bit-exact, regression-tested). The plugin uses the shared modulation module, so its future routing pass is a target table.
- MIDI Chord Arp Scale Tool (`plugins/MidiEffect`, plugin code `Marc`): a sixth plugin, MIDI effect with stereo pass-through per plan 06 idea 2.11. Incoming notes are quantised to one of the suite's six scales (reusing `CoreDSP::Sampler::quantizeToScale`) and chorded (shared `ChordEngine.h`: eight qualities, four arp orderings); the octave parameter transposes the chord and the velocity parameter scales note velocities. Note-off releases the whole chord, and a retrigger releases the previous chord first, so nothing sticks. Root shows as `C4 (60)`.
- Pendulum LFO shape (plan 06 idea 2.1): appended as shape index 7 to the shared `suite_modulation` router and panel (append-only, old saved indices keep their meaning), so every plugin's LFO can now select it. A damped swing whose amplitude decays with the unwrapped cycle count. DSP tests cover the decay at known cycle positions and every shape staying in [-1, 1].
- Brand lockups for the two new plugins: one `tools/brand/lockups.py` table row each (`lockup_stereo_tool.png`, `lockup_midi_effect.png`), generated from the family template and embedded through the `LOCKUP` build argument, drawn in the editors' headers the same way the other four plugins do. The new plugins' editor tests write per-page renders when `SUITE_RENDER_DIR` is set (plan 05 R9).
- The two new plugins register as CTest entries: `StereoTool_PluginTests`, `MidiEffect_PluginTests` and a VST3 host-load test each. `suite_add_plugin` now skips a plugin's bank preset-test target while `<Name>PresetTests.cpp` does not exist, so new plugins do not break bank builds before their factory presets are authored.
- The preset bar's selection now survives the plugin window being closed and reopened (plan 09 1.4, all four plugins): the identity of the applied preset (which factory preset, or which user preset file) lives in the processor instead of the editor-owned bar, and the bar restores it when the editor is recreated — it used to always show INIT after a reopen. The identity also travels in saved sessions and host program dumps as the additive `presetSelection` property on `<PARAMETERS>` (owner decision D3; the `lerpCurve`/`samplePath` pattern, no state-version bump — the plugins are unreleased and a session without the property simply reads as Init). The dirty `*` survives a reopen too: a restored bar's clean baseline is the state the preset produces. User presets are identified by file path, so renaming or rescanning cannot confuse the bar; a user file that no longer exists falls back to Init without touching the audio state. The bar exposes `getCurrentPresetName()`/`isPresetDirty()` for tests, and its 10 Hz timer follows selection changes made by another editor of the same processor. The host program bridge and the bar's selection describe the same event: `setCurrentProgram` updates both. No parameter or `numControls` change, no new test executables; the CTest entry counts stay 11 (default) / 15 (bank).
- Sgraffito presets and host sessions now carry the sample they were made with (plan 07, phases 1-4): a `samplePath` property on the saved `<PARAMETERS>` tree (an absolute file path or an `embedded:` URI, not a parameter), so changing presets changes the sample the way other parameters do. A preset without the property leaves the sample alone; INIT and host program 0 reset the sample to the embedded factory default. A path that cannot be found is searched for by file name in `userDocuments/AudioSuite/Sgraffito/Samples`; if it is still not found, the current sample keeps playing and the waveform view draws a "Sample missing - click to locate" overlay whose click opens the sample browser. Loading a sample marks the session dirty for the preset bar's SAVE indicator, which is intended: the sample is part of the preset. No parameter or preset-format change. Phase 3: the bank audit guards the sample property. Phase 4: file samples load in the background (the current sample keeps playing until the load installs, so the interface never stalls on a big file; the latest request wins), and five Sgraffito factory presets (the cloud group) ship the embedded cloud sample variant — the bank may carry `embedded:` URIs, never file paths (audit-enforced).
- Sgraffito: the host program list works behind `SUITE_PRESET_BANK_AS_PROGRAMS` (plan 07 test 11 found Sgraffito was the one plugin without it). Program 0 is INIT and programs 1..20 are the factory presets in bank order; program changes are guarded and reset `currentProgramIndex` when a non-program state is applied. No change with the flag off.
- Sgraffito Memory Sampler: a fourth plugin. The keyboard is a timeline through the sample (Scrub), Chop divides the sample into slices, Cloud plays grains that wrap around their region, and Swell plays in reverse with a crossfade. Scale Lock quantises played notes. Two LFOs and six modulation routing slots move 25 controls. The editor's SOUND page shows the sample waveform with the region and Chop slice lines, and a key map strip with the root key, the locked scale and the active voices. A mode banner shows the active mode. Factory sample embedded (WAV), so the plugin makes sound out of the box.
- Sgraffito factory presets (20) behind `SUITE_PRESET_BANK`.
- Factory preset coverage (plan 05.3 F1.3, resolved 2026-11-12): preset coverage findings are now recorded owner decisions — output levels/gains are never authored by factory presets, and the structural LFO/routing slots stay at their defaults. Sgraffito gained five new factory presets (Velvet Swing, Ghostly Echo, Held Breath, Fine Grained Drift, Slow Attack Tape) that use the attack and release envelopes and showcase the performance controls (swing, ghost notes, sustain hold, pitch/velocity shaping, tape stop); the suite-wide bank is now 100 presets.

### Fixed
- Test-suite coverage restored in `CoreDSPTests`: the "every shape stays in [-1, 1]" loop had been narrowed from all seven shapes to the four periodic ones while the pendulum shape was added (the fix for a failing whole-cycle check had been applied to the wrong loop). It now covers every shape including the pendulum, and the whole-cycle check keeps its original scope (the shapes that do not depend on the cycle index).
- The two new plugins' first commits (plan 06 ideas 2.9/2.11) never compiled and were never registered as tests — the build directory had not been reconfigured and build output was discarded, so CTest kept reporting the stale 16 entries. Fixed by reviewing the branch against the plan: `suite_add_plugin`'s flag arguments were passed with stray `TRUE` values (a configure-time `FATAL_ERROR`), the MIDI effect declared a `processBlock` signature that no base virtual has, its enumerators contained a space, the parameter pointers used `std::atomic<int>` where JUCE supplies `std::atomic<float>`, the root parameter was a broken 100-entry choice, the stereo tool's width collapsed the image to mono at its default and its dry/wet mix was inverted, and the editor referenced widgets that do not exist. The plugins were rewritten against the suite contracts (MTC's stereo pass-through buses, `CoreDSP` engines, `SuiteUI` widgets) and the missing `add_subdirectory` and host-test registrations were added.
- MIDI velocities: `MidiMessage::getVelocity()` is the raw 0-127 byte; the 0-1 float is `getFloatVelocity()`. The chord tool initially scaled the raw byte and clamped it to full velocity.
- JUCE rejects `/` in product names (it becomes a path separator in the shared-code artefact name); the MIDI plugin's product name is now "MIDI Chord Arp Scale Tool".
- Plugin codes follow the suite's four-letter style: `Ster` (Stereo Tool Effect) and `Marc` (MIDI Chord Arp Scale Tool), replacing `STS_`/`MCAT`. Nothing is released, so the codes are still free to change (owner decision: codes are set when development starts).
- Plan 10 (the owner's nine Sgraffito findings, executed 2026-11-18). **Mode affinity (finding #1):** the controls only one mode can use — Slice Count (Chop), the three grain knobs (Cloud), the two swell knobs (Swell) — are now disabled (dimmed, never hidden, decision G1) outside their mode via the editor's `updateModeAffinity()`, and Slice Count moved from the CLOUD group into the TAPE & MEMORY row where it belongs. **LOAD SOUND (finding #2):** the button sat at the waveform's vertical middle because its child-of-waveform bounds were computed from the waveform's editor-relative `getBounds()`; it now uses `getLocalBounds()` and sits top-right inside the preview, as requested. **Attack and Release (finding #3):** a direct note-on allocated its voice with `envStart = 0.0`, tens of thousands of samples behind the playhead, so the attack ramp was always finished (ATTACK did nothing on most notes); and with the default 400 ms Tape Stop Time every note-off took the tape-only branch that never set `envEnd`, so RELEASE never shaped the tail. Direct notes now start their envelope at the absolute stream position, the release envelope always runs (the tape ramp multiplies on top, decision G2), and a released voice ends only when both are finished. The SOUND page's waveform view also gained an envelope preview: the attack/sustain/release line of the displayed key's region laid over the waveform (decision G3). **Root Key and Region Span (findings #4/#6, decision G4: no rename):** Root Key is now the pitch centre — `rate = 2^((key − rootKey)/12)`, so the root key's note plays the sample at its natural pitch (the old centre was a fixed middle C and the knob did nothing) — the never-read `rootKey` argument was removed from `CoreDSP::Sampler::keyRegion`, and the Region Span ↔ key ↔ Root Key relation is documented in the new per-control help texts. **Status bar (finding #5):** a help line below the keyboard shows the control under the pointer's help text, driven by a shared `SuiteUI::HelpTracker` (the fourth editor to use this pattern, the first three keep their local copies); every control now has a help text, honest about anything not wired yet; the bar honours the settings' `ui/tooltips` toggle (decision G5). **Sample switch-back (finding #7, decision G6):** the delta rule is pinned by a new test (a preset with a sample switches back to it; a preset without one keeps the current sample; INIT resets), and the preset bar explains the rule in its help text. **Samples and presets (finding #8, decision G7):** `tools/sgraffito_samples.py` generates one deterministic, seeded sample per factory preset (20 WAVs, 48 kHz mono 16-bit, 2–3 s each, ~5 MB embedded total — the plan's ≈2 MB estimate had an arithmetic slip: 3 s at 48 kHz/16-bit is ~288 kB, not ~115 kB), each designed to showcase its preset (bells for Glass Dust, drone for Deep Cloud, breaks for Tape Break, …); every preset now carries `sample_path="embedded:<slug>_4k.wav"`, so selecting a preset always loads its sample; the old `cloud_4k.wav` variant is retired; the preset deltas were overhauled to reference only live controls (the inert `driftAmount`/`glide`/orphan-ghost/cloud-in-non-cloud-mode references are gone) — Deep Cloud's Root Key moved to 84 so its "low" description survives the new pitch-centre semantics. **Settings dialog legibility (finding #9, phase 5b):** the dialog was readable only by luck — a top-level window inherits the host's look and feel, whose light text colours sat on the dialog's white paint (the owner's screenshot shows everything invisible). The dialog now owns a component-scoped `SuiteUI::SuiteLookAndFeel`, paints the suite's dark panel with explicitly coloured captions, values and BROWSE buttons, and the window background matches; the `SuiteSettingsTests` dialog smoke test now asserts the panel colour, the drawn caption pixels, and the button-text pixels per pixel. One caveat found and fixed on the way: a JUCE `FileOutputStream` **appends** to an existing file, so the test's PNG record had to delete the old file first (otherwise every run archives another PNG and decoders read the oldest one).
- Dynamic Saturation: the MOD page's transfer-curve preview sat behind the modulation grid (the layout gave the curve the whole page and drew the group over it, so only the curve's diagonal peeked out below the routing rows). The curve now gets the strip above the group, and the group gets its natural height from the new `SuiteModulation::ModulationPanel::getPreferredHeight()`, mirroring SpectralDrift's MOD-page split. SuiteModulationTests gained the panel-height check (now 10 functions). Renders under `build/renders/mod-page/`.
- Sgraffito Cloud mode: crackling that built into a clipped wash, then silence. Four defects compounded. (1) The whole voice state machine ran once per output **channel**, not per sample: stereo output advanced every voice twice as fast, so Scrub/Chop/Swell played at double speed and one-shots ended after half the region, and in Cloud mode the second channel read grain positions the first pass had already moved — decorrelated left/right stepping, the reported crackle. The state machine now runs once per output sample and each voice's contribution is read per channel (a mono sample still feeds every channel). (2) The memory decay's gate compared a 0–100 % parameter (default 20) against a 0.5 threshold, so every voice's gain faded exponentially toward true silence at the defaults — the "sound disappears completely". The fade now goes toward `1 − amount`, so the default of 20 % keeps an 80 % floor and only a full Memory Amount fades a note away. (3) The tape-stop ramp ticked once per block but decremented by one sample's worth, so the default 400 ms release ramp took minutes, and the returned level factor was ignored — released voices kept sounding at full level and piled up in the 32-voice pool. The ramp now ticks per output sample and its level multiplies the voice's output, so a released note fades and frees its slot in real time. (4) Dust/Crackle/Wow/Flutter multiplied their factors straight into `voice.rate`/`voice.gain` once per block, so any nonzero amount grew exponentially (clipping, runaway rate, grain-wrap loops spinning); they are now bounded per-block factors recomputed from the voice's own phase state. Also: a UI-keyboard note-off released at stream sample 0, which the old `envEnd > 0.0` deactivation test turned into a silent zombie holding its pool slot (`>= 0.0` now, and the release uses the block start); and grain and Scrub reads are linearly interpolated (`readLinear`) instead of integer-truncated, removing the stepping crackle at high rates. Three new regression tests: Scrub still playing past 24 000 samples, Cloud holding its level in stereo over a full second with exactly identical L/R output, and a tape-stop release freeing its voice inside 0.64 s. No parameter, state or preset change.
- Opening the Settings dialog crashed the host. The dialog built its rows through four namespace-scope global structs holding raw pointers to its child components; the first open dereferenced a pointer that was never assigned (a null crash on the very first click, in any of the four plugins), later opens used dangling pointers to the destroyed dialog's children, and the async folder-chooser callbacks could outlive the dialog. The dialog now owns every row as a component member (no state is shared between dialog instances), the browse buttons and toggle are wired up (they had a handler but were never connected), the folder chooser is held by the dialog and its callback is SafePointer-guarded, and the fallback tempo is a proper horizontal 20–300 BPM slider. The Sgraffito sample-search-folder row now appears only in Sgraffito (the header comment promised this but nothing implemented it); the other three plugins get the three common rows. `SuiteSettingsTests` constructs and paints the dialog (both variants, twice on one store), which is the regression this fix needed all along — the old tests never built the dialog, which is why a guaranteed first-click crash shipped green.
- Sgraffito: a released voice now frees its pool slot when its release envelope ends, instead of staying active until the region end (which could take several seconds and left the voice counter stuck). Tape-stop voices keep their own completion path.
- Sgraffito: `Sustain Hold` is now a modulation target. It was in the `ModTarget` enum but missing from the target table, so the routing choice list was one short and every target from Ghost Threshold onward moved the wrong control.
- The macOS build's tests failed on `testOffsetControlIsUsable`, because Apple clang fused a multiply and an add on arm64 and left the LFO Offset default at 1.5e-6. Apple clang is now built with `-ffp-contract=off`, so macOS arithmetic matches Windows.
- Sgraffito: the sample region maths treated the per-cent Region Span and Region Length values as fractions, so every note played the whole sample. The lay-back path now uses the same `CoreDSP::Sampler` maps as the direct path, and the waveform display mirrors them. Cloud mode advanced grains with a nonexistent field and wrapped at the wrong scale, and wrote into the wrong buffer positions; the memory-trace decay ran per sample with the block length as exponent, which silenced the output almost immediately. A mono sample no longer reads a second channel that does not exist.

### Added
- `tools/new_plugin/new_plugin.py`: creates a new plugin from a skeleton, and refuses a plugin code that is already in use. Developer tool; no change to the plugins.
- `modules/suite_modulation`: a shared module with the two LFOs, six routing slots, the LFO scope, the modulation panel and the control display, for plugins to reuse. Its tests (`SuiteModulationTests`, 9) run as a new CTest entry.
- `tests/common/ModulationTestUtils.h`: `setLfo`, `setRoute` and `timingOffsets` for any processor with the shared LFO parameters.
- `modules/core_dsp/include/ModulationTiming.h`: the division table, `fractionalPart` and `cyclesFromSeconds`, with DSP tests.
- Spectral Drift Shifter: fourteen controls in total. Drift Depth, Bin Spread, Stereo Phase, LFO Shape (sine, triangle, saw, square), Spectral Shift (±32 bins), Spectral Tilt (±2), Spectral Gate, Feedback Damping, Drift Start and Output Gain.
- Dynamic Saturation Companion: thirteen controls. Attack, Release, Detect HPF, Stereo Link, Tube Bias, Fold, Tone and Envelope Curve are new.
- Dynamic Saturation Companion now runs its shaper at 2× oversampling. The latency is reported to the host.
- Spectral Drift Shifter and Dynamic Saturation Companion: the shared two LFOs and six routing slots, with a SOUND/MOD page in each editor. Mix, feedback, feedback damping and output gain are smoothed per sample, so modulating them does not zipper.
